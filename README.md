# Pose Studio — Minecraft Java 1.20.1 / Forge

在 Minecraft 世界内摆放实体、编辑静态姿势、移动独立摄影机，最后用 F2 截图。世界、资源包、光照和渲染由 Minecraft 提供。

**本版本只做静态 Pose。没有时间轴、关键帧、播放、IK、布料或自制渲染引擎。**

## 安装

1. 使用 Java 17、Minecraft Java Edition **1.20.1** 和 Forge **47.4.10 或同一 47.x 系列的兼容版本**。
2. 将 `release/posestudio-0.1.10.jar` 放入目标游戏实例的 `mods` 目录。
3. 单人世界直接使用；多人世界需要客户端和服务器都安装此模组，操作者需要 OP 等级 2。
4. **不要安装**带 `verification-fixtures` 后缀的测试夹具 JAR。

实际测试版本包括 Forge 47.4.10 和 47.4.22；v0.1.2 已验证 Oculus 1.8.0 + Embeddium 0.3.31 + ComplementaryShaders v4.7.2 的光影组合，其他整合包未逐一测试。

## 中英双语界面

v0.1.1 跟随 Minecraft 的语言设置。打开 **选项 → 语言 → 简体中文（中国）** 即可显示中文；选择 **English (US)** 显示英语，其他语言回退为英语。切换语言后重新打开 Studio 面板即可。

按钮、属性、状态提示、权限错误、文件错误以及常用骨骼节点均支持中英文。中文界面中的“角色 / 姿势 / 摄影机”分别对应 Actor / Pose / Camera；“冻结 / 恢复 / 应用 / 拍照”分别对应 Freeze / Restore / Apply / Capture。

已有 Pose JSON 仍使用原来的稳定骨骼键名，加载方式不变。第三方模组自定义、未知骨骼名称会保留原名，实体名称使用 Minecraft 或对应模组自己的语言资源。姿势文件名仍使用英文字母、数字、下划线和短横线。

更新时移走旧的 `posestudio-*.jar`，只安装新的 `posestudio-0.1.10.jar`，避免同一模组重复加载。保留游戏实例的 `posestudio/poses` 目录即可继续读取已有姿势。

## v0.1.10：添加实体后动作界面自动就绪

添加实体后即可返回动作界面；新实体和模型部件到达时，当前界面会自动绑定可编辑骨骼及正确数值，无需退出重开。尚未收到模型部件时会提示同步状态。正常输入时保持焦点与未提交的数值。详见 [验收](docs/ACCEPTANCE-0.1.10.md)。

## v0.1.9：头部与身体节点间距

人形模型的头部编辑节点放在面部方块的中心（面部两条对角线交点），身体节点放在躯干中心。节点显示、鼠标拾取、辅助连线和旋转环使用同一显示位置；位置随模型姿势和 Actor 整体变换同步。原来的模型旋转原点、姿势数值与 JSON 格式不变。详见 [验收](docs/ACCEPTANCE-0.1.9.md)。

## v0.1.8：完整物品目录与冻结时分离装备

“添加”分为“实体 / 物品”。物品同时读取所有非空气注册物品和当前世界创造物品栏的完整变体；TaCZ 枪械可以按名称、Mod ID、注册 ID 或 GunId 搜索。添加时保留枪械 ID、附件、皮肤等 ItemStack 数据；原版物品与 Mod 物品均可成为独立摆拍对象。

冻结角色时，主手与副手的非空物品自动分离到角色旁边，角色空手并从模型的中立站姿进入编辑。分离出的物品在角色列表中独立显示，在 Actor 模式调整位置和自由旋转；未提供可读取 ModelPart 的枪械只能整体编辑。恢复角色或退出 Studio 时，将完整原装备还原到原来的热栏位置及副手，并清除展示副本。

分离物品计入非生物预算；超限时拒绝冻结，装备保持原状。生物默认 8（5–10），非生物默认 25（20–30）的两类预算不变。已有 Pose 编辑和关节实现保留。新协议为 5，多人两端需更新同版。详见 [修复说明](docs/BUGFIX-0.1.8.md)。

兼容复核覆盖当前包同时加载的 SkinLayers3D、EMF / ETF、Physics Mod、TaCZ / TaCZ Tweaks、CarryOn，以及 Wildfire Gender + FemalePlasticSurgery 的附加身体层。冻结时处理爬行 / 游泳渲染偏移、搬运手臂姿态和附加身体层的动态覆盖。CustomSkinLoader / SimpleBedrockModel 的普通 64×64 皮肤路径参与组合测试；网络皮肤服务和专用 Bedrock 自定义模型未逐模型验收。具体版本与实际测试范围见 [0.1.8 验收](docs/ACCEPTANCE-0.1.8.md)。

## v0.1.7 收工版：Actor 整体自由旋转与独立物体预算

Actor 面板新增 Roll，整体 Yaw / Pitch / Roll 支持任意角度（每轴有限数值 ±36000°），Pitch 不再只限于 ±90°。点击“整体操作：位移”切换为旋转，再选 X / Y / Z，拖动旋转环或模型：X 俯仰、Y 偏航、Z 侧倾。多选时各对象在自己的原点转动，增加相同角度，不绕组中心公转，不改变位置或内部关节。一次完整拖动记一次撤回，保留十步历史。

整体旋转包裹实体原来的 Minecraft / Mod 渲染路径，因此不依赖某种生物原生是否支持 Pitch 或 Roll。实体位置和姿势继续保留，选中框、拾取与标准视角焦点跟随旋转，Capture 保持旋转结果。正常游戏及退出后恢复原生渲染。多人双方须更新到同版；网络协议升级为 4，旧版协议不混用。

参与摆拍的预算分开计算：**生物 / 玩家默认 8，可配 5–10；非生物物体默认 25，可配 20–30**。对应存档 `serverconfig/posestudio-server.toml` 中的 `maxStudioActors` 和 `maxStudioProps`，同维度共享。非生物包括掉落物、载具、投射物和 Display 实体；盔甲架继承 LivingEntity，计入生物预算。按启动键仍收集当前可见对象与本人，任何一类超限都拒绝进入，成功时一起冻结。数值是 Studio 参与预算，不是隐藏普通背景实体或保证帧率。

批量消息最多 40 对象，支持 10 生物 + 30 非生物共同移动、旋转及撤回。原来的五字段 Actor JSON 缺失 Roll 时按 0 读取。实体目录创建 `minecraft:item` 时提供默认铁锭，避免空物品不渲染；本版没有新增大型物品资产库。

项目至此停止功能扩展。构建、单元测试与指定 Vanilla-tacz 实例的最终复核见 `docs/ACCEPTANCE-0.1.7.md`。发布包含完整源码、正式 JAR 和 SHA-256；测试夹具不进入正式 JAR。

## v0.1.6 编辑往返、标准视角、三轴位移与十步撤回

摄影机面板可以进入自由摄影，也可返回之前的动作编辑。自由摄影或 Capture 中按当前编辑面板键或 Esc 返回，保留姿势、位置、冻结、选中关节和全部摄影机参数；无需退出 Studio。编辑界面按 Esc 收起面板进入自由摄影，再按 Esc 回到编辑。

中央顶部“前视 / 后视 / 左视 / 右视”以所选对象朝向为基准，镜头对准模型中心。它们是原生透视镜头的快捷位置，支持当前 FOV 与模型体型，并可撤回。

Actor 模式右侧 X / Y / Z 选择世界位移轴，中央彩色手柄对应红 X、绿 Y、蓝 Z。拖手柄选轴，或在模型上左 / 右拖沿当前轴移动，只有该坐标发生变化。Ctrl 多选后全组共享同一位移。镜头正对某轴时有偏移深度手柄，上下拖即可移动该轴，不必先转镜头。

撤回最多保留 **10 次**完整调整，超出丢弃最旧记录，一次完整鼠标拖动只占一次。切换编辑、摄影和拍照保留历史；解除冻结、移除对象或退出会清空。Ctrl+Z 或顶部“撤回”逐次恢复，不提供 Redo 或动画功能。

启动 / 编辑面板 / 拍照动作可以在 Minecraft“控制 → 按键绑定 → Pose Studio”修改。界面页脚、自由摄影返回提示读取当前键位，每次绘制时更新。默认键为 F6 / F7 / F8；指定实例实际启动绑定为 F4，界面会显示 F4。自由摄影的返回提示在 Capture 中完全隐藏。

详情见 `docs/BUGFIX-0.1.6.md` 和 `docs/ACCEPTANCE-0.1.6.md`。以下兼容说明保留历史；操作流程按本版更新。

## v0.1.5 生物头部、实体发现与场景添加

Fresh Animations 的骷髅把可见头部放在 headwear，而 head 是空节点。Humanoid 的头部与头部外层现在共用 head 编辑变换，位置和三个旋转轴同步生效，不替换资源包模型。默认隐藏 EMF 内部辅助部件；需要查看全部模型层级时开启“辅助”。

左侧角色列表列出客户端已加载实体，按摄影机距离排序，不再固定筛选玩家身体周围 96 格。客户端尚未收到、所在区块未加载的实体无法列出；摄影机不会生成远方区块。

顶部“添加”打开当前整合包的实体注册目录。可以搜索中文名称、注册 ID 或 Mod 命名空间，选择实体，再点击“放到当前镜头前方”或输入 XYZ、Yaw、Pitch，最后点击“添加并冻结”。返回面板后自动选中新增对象，使用“角色”模式布置整体位置与朝向，使用“姿势”模式编辑它已有的 ModelPart。普通生物不增加肘膝关节。

新增对象为临时摆拍实体；“移除”只删除新增对象。退出、断线、切换维度和服务端正常停止会清理它们，已有实体仍按原快照恢复。为防止崩溃后残留，带临时摆拍标记且没有活动锁的对象在重新载入时不保留。当前只保存单个 Pose，不保存整场景。摆放范围为玩家 512 格内且目标区块已加载。

冻结同时拦截生物的消失检查，避免和平难度或距离消失把摆拍对象删除。Physics Mod 的可选桥接阻止冻结 / 临时移除对象触发死亡碎裂，不改变其他实体的物理效果。

目录展示全部注册类型，但并非每一种都能默认创建或提供可编辑骨骼。例如玩家实体需要真实玩家连接，部分投射物需要专用生成数据；此类类型会报告无法创建。独立模型库无法读取 ModelPart 时仍可布置 Actor，姿势编辑按适配器能力降级。不能据此认定所有 Mod 的专用模型库都已适配。

本版的游戏验证仍只使用指定的 Vanilla-tacz 原实例及其原资源包、光影设置，详见 `docs/BUGFIX-0.1.5.md`。

## 启动定格、数量上限与整体拖动

按当前 Studio 启动键时，从当前主画面的实体渲染列表收集参与对象；光影的阴影 pass 和界面预览不算入。玩家本人始终加入，包括从第一人称进入时。全部对象先在服务器统一检查，再一起冻结。若当前画面加玩家本人超过上限，显示数量提示并暂不进入 Studio；若权限、骑乘、锁所有权或实体状态不符合要求，同样不部分进入。摄影机保留按启动键时的位置。

**生物 / 玩家默认上限 8，允许配置为 5–10；非生物默认 25，允许配置为 20–30。**单人世界修改 `<存档>/serverconfig/posestudio-server.toml` 的 `maxStudioActors`；专用服务器修改其世界的同名 serverconfig 文件。所有操作者在同一维度共享预算，玩家、冻结的已有实体和新增模型按 LivingEntity / 非 LivingEntity 分别计入。5 适合较重光影或较弱设备，8 是默认值，10 应在本机帧率可接受后使用。这是参与 Studio 的摆拍对象预算，不是对 Minecraft 所有普通背景实体的渲染截断，也不是帧率保证。切换镜头后看到的新对象需要另外冻结，并受同一上限约束。

在“角色 / Actor”模式：

- 左侧列表或视口点击单个模型；Ctrl 点击增减多选。
- 在已选中模型上按住左键或右键拖动，沿当前选定的世界 X / Y / Z 轴平移整个模型或选中组；也可直接拖动对应的彩色手柄。不会修改关节位置、局部姿势或摄影机。模型命中优先于摄影机操作。
- 多选后点击已经选中的模型会保留整个组；点击未选中的模型会变成单选。全部选中对象必须已冻结。
- 右侧 Position X/Y/Z 可精确调整三轴。多选时以当前主对象为基准，把相同位移应用到整个组；Yaw/Pitch 的数值变化同样应用到组内每个对象，保留组内相对位置。
- 一次完整拖动记为一次调整；“撤回”或 Ctrl+Z 一次恢复整个组选中对象。服务器先验证组内所有目标，任何一个无效都拒绝本次整体移动。

“姿势 / Pose”模式的左键节点、旋转环仍只调整关节，右键继续平移摄影机。“摄影机 / Camera”模式用于镜头参数。在三种模式的空白视口，左拖转动、右拖平移镜头；滚轮或中键上下拖动调整 FOV。切换模式、隐藏面板或进入拍照模式会结束正在进行的模型拖动。

战术扩展投掷物的默认实体工厂没有物品模型 ID，会出现紫黑占位方块。针对本包的 LrTactical 使用其服务端原生资源索引和实体工厂补齐 Item 数据；没有安全生成数据时报告无法创建。它仍不暴露 ModelPart，因此只支持整体布置，不能编辑其内部骨骼。

## v0.1.4 实际资源模型兼容与单次撤回

修复 FA+Player / EMF 把实际几何放在 ModelPart 子节点时，肘膝节点虽然存在、但可见模型不弯曲的问题。连续变形沿肢体层级传递到子节点；EMF 自己的 compile 覆盖方法也接入变形。保留资源包的模型、UV、纹理和光影，不用原版模型替换 CEM 模型。

冻结时停止当前角色的 EMF 动画，并让底层和外层使用同一位置、旋转和缩放快照，防止呼吸或 idle 对外层持续覆盖。退出 Studio 后恢复正常渲染和动画。

默认只显示玩家主要关节及一个旋转环。右侧的 X / Y / Z 按钮选择当前旋转轴；从正面看到侧向旋转环呈一条线时也可以拖动。顶部“辅助”按钮开启完整节点、连线与包围框；肘膝属性仅显示三个可编辑旋转数值。

顶部“撤回”或 Ctrl+Z 撤回上一次调整。一次鼠标拖动作为一次调整，不会把每个鼠标事件拆成多个步骤。姿势数值应用、旋转环拖动、加载姿势和面板摄影机操作都能撤回；该历史版本只保留一次调整；v0.1.6 已改为十次历史，仍无 Redo 或动画时间轴。

本次只在指定的 Vanilla-tacz 包中做游戏验证，包含实际启用的 FA+Player、Fresh Animations、完整模组与原光影配置。最终直接在原实例目录用离线玩家、新建验收世界测试；双色皮肤和实例保存的皮肤图各通过 98 项检查。原选项与配置恢复，测试夹具与临时皮肤包移出。详情见 `docs/BUGFIX-0.1.4.md`。

## v0.1.3 双层皮肤与鼠标视口控制

玩家底层和帽子、外套、袖子、裤腿共用对应的骨骼与姿势，不需要分别选中两层。肩、髋整体移动，肘、膝连续弯曲时，两层一起变形。贴图仍为原来的普通 64×64 皮肤，透明区域和外层厚度保留，不要求重做皮肤。

Skin Layers 3D 的独立体素网格通过可选桥接参与同一肘膝弯曲，保留原模组的网格、纹理和光影渲染路径。未安装 Skin Layers 3D 时正常使用原版双层。类似模组若仍使用可访问的 ModelPart，可通过通用适配器处理；完全独立的网格格式需要自己的桥接，不能保证所有皮肤模组通用。

中央视口支持滚轮或按住鼠标中键上下拖动缩放、空白处左键拖动旋转视角、右键拖动平移视角。选中节点和旋转环优先进行姿势编辑。左侧列表的滚轮只滚动列表，右侧输入框不会触发摄影机移动。缩放调整摄影机 FOV，不改变角色或模型大小。

验证范围和实现说明见 `docs/BUGFIX-0.1.3.md`。

## v0.1.2 光影兼容修复

修复 Oculus/Embeddium 的实体快速渲染绕过节点捕获和肘膝网格的问题。模型读取在选择实体时完成；尚未冻结时会提示点击“冻结”，不再无限显示“等待角色渲染”。冻结后若镜头没有渲染到角色，也会在 3 秒后给出明确提示。光影和世界渲染继续由原整合包提供。

详细原因、修复范围和验证记录见 `docs/BUGFIX-0.1.2.md`。

## 完整编辑流程

1. 进入世界后按当前 **Studio 启动键**（默认 F6，本实例为 F4）。当前可见实体与玩家本人一起冻结后打开 Studio；超限时提示并拒绝进入。左侧列出客户端已加载实体。
2. 初始画面内对象已冻结；后来另外选中的未冻结实体需点击 **Freeze / 冻结**。按钮变为 Restore 后表示服务端已确认。
3. 在 **Actor** 模式选择 X / Y / Z 轴，再拖动模型或轴手柄布置整体位置，Ctrl 点击多选后一起移动；也可输入 Position X/Y/Z、Yaw、Pitch、Roll，点击 Apply 或回车。
4. 在 **Pose** 模式点击左侧部件名称，或中央视口对应的白色节点。
5. 拖动旋转环修改姿势：红色 X、绿色 Y、蓝色 Z。也可以输入 Rotation X/Y/Z，点击 Apply 或回车。角度单位是度。
6. 玩家 `left_arm` / `right_arm` 表示肩部的整体旋转；`left_leg` / `right_leg` 表示髋部的整体旋转；四个额外节点分别是 `left_elbow`、`right_elbow`、`left_knee`、`right_knee`。
7. 普通实体显示它自身的已有 ModelPart；不会为生物增加新关节。可访问部件支持旋转和 Local X/Y/Z，局部位置单位为模型像素（16 像素 = 1 格）。
8. 按当前 **编辑面板键**（默认 F7）关闭面板，直接驾驶自由摄影机。再次按该键或 Esc 返回编辑器。面板内中央视口支持空白处左拖旋转、右拖平移、滚轮或中键上下拖动缩放。
9. 按当前 **拍照键**（默认 F8）进入 Capture，隐藏编辑面板、节点、辅助线、旋转环、包围盒与原版 HUD。Pose、Actor 和 Camera 不会因切换而重置。Studio 期间隐藏原版聊天叠层，近期操作提示也不会盖住截图。
10. 按 **F2** 使用 Minecraft 原生截图。按拍照键、编辑面板键或 Esc 返回面板，按当前 **Studio 启动键** 退出 Studio 并恢复冻结前的实体状态。

Esc 在编辑面板和自由摄影之间往返，Studio 仍在运行；Capture 中 Esc 返回编辑。结束摆拍请按当前 Studio 启动键。切换维度、断开连接和服务器正常停止时会释放实体锁。

## 摄影机控制

| 控制 | 效果 |
|---|---|
| WASD | 相对于摄影机 Yaw 水平移动 |
| Space / 左 Shift | 上升 / 下降 |
| 鼠标 | Pitch / Yaw，与玩家身体朝向分离 |
| Q / E | Roll |
| 左 Ctrl | 四倍移动速度 |
| `[` / `]` | 减小 / 增大 FOV |
| Camera 面板 | 数值设置 XYZ、Pitch、Yaw、Roll、FOV、Speed |
| 面板视口空白处左键拖动 | 转动摄影机 Pitch / Yaw |
| 面板视口空白处右键拖动；Pose / Camera 模式右拖 | 沿摄影机画面平面移动，保留朝向 |
| 面板视口滚轮 / 中键上下拖动 | 缩放摄影机 FOV，范围 10–150° |

FOV 范围 10–150°，默认移动速度 5 格/秒。摄影机可以穿过方块，当前位置完全独立于玩家。可观看的范围仍受客户端已加载区块和游戏视距限制，摄影机不会自行让服务器加载远方区块。

编辑器会在 Studio 期间适当减小过大的 GUI 缩放，保证面板能显示；退出时恢复原 GUI 缩放。建议窗口至少 854×480。

## 保存和读取

Pose 面板中输入文件名，再点击 Save / Load。小窗口也可使用 Ctrl+S / Ctrl+O 打开文件名对话框。

文件放在**当前游戏实例**的 `posestudio/poses/<name>.json`。文件名只允许英文字母、数字、`_`、`-`，不接受路径。文件保存实体注册 ID、Actor Transform、部件名、旋转和位置；JSON 使用度，不使用弧度。

Load 会立即应用匹配实体类型和已有部件名称的 Pose，保留当前摆放位置。保存的 Actor Transform 可作为布景记录，在 Actor 面板设置。没有 Pose Library 或场景资产管理系统。

## 行为和兼容边界

- Freeze 具有服务端实体锁。普通生物停止实体 tick、AI 和重力；冻结玩家的移动及交互输入在服务端被拦截。原始位置、朝向、速度、AI 和重力状态保存在会话中，Restore / Exit 时恢复。
- **Pose 是本地摄影视图，Actor 位置与冻结由服务器管理。**其他玩家不会自动看到你的自定义关节 Pose，本版本没有多人协同 Pose 同步。
- 玩家手臂、腿及对应皮肤外层使用原 baked cube 的 UV，支持普通 64×64 皮肤和 slim / classic 几何。弯曲区是一段连续细分网格；直立时调用原版 cube 渲染。
- 原版盔甲模型可通过已有 humanoid 部件读取，手持物跟随编辑后的肩与腕。自定义装备、特殊附加层和复杂物理效果没有承诺完整适配。
- 通用 Adapter 只检查已知 Model、ModelPart 和 RenderLayer 容器，最多 512 个部件，身份去重后读取已有 children。无法安全读取的 renderer 显示 Unsupported / Partial 提示，仍可编辑 Actor。
- GeckoLib 等独立骨骼/渲染库、完全替换 PlayerRenderer 的 Mod、绕开 ModelPart 渲染的优化实现，可能无法显示或编辑 Pose。没有为它们重建模型。
- 使用 Minecraft 的现有 VertexConsumer、RenderType、纹理、光照和世界渲染。已测试下述发行记录中的 Oculus / Embeddium / Complementary 组合；该结果不能视为所有光影、资源模型或独立渲染模组的兼容证明。
- 可在已有模型的局部位置继续调整，但玩家新增肘膝的位置由肢体网格决定，仅编辑其 XYZ 旋转。默认没有关节限制；极端旋转允许自交。
- 已骑乘或承载乘客的实体需先下马。冻结范围限操作者身体周围 96 格；Actor 编辑的 Y 范围为 -2048 到 2048。
- 会话不作为持久场景保存。正常退出能恢复状态；进程崩溃不提供持久锁快照恢复。

## 开发与验证（全部写入 E 盘）

当前工程根目录固定为 `E:\PoseStudio`。开发 JDK 位于 `.toolchain/jdk17`，Gradle 用户缓存位于 `.toolchain/gradle-user-home`，Java 和原生库临时文件位于 `.toolchain/temp`。请使用 `studio.ps1`，不要直接使用默认环境运行 Gradle。

```powershell
Set-Location E:\PoseStudio
.\studio.ps1 test build --offline
.\studio.ps1 runClient --offline
.\studio.ps1 runClient -Pacceptance --offline
```

源码包不包含大型 `.toolchain` 缓存。在另一台机器使用源码时，需要将 Java 17 JDK 解压到 `.toolchain/jdk17`，首次构建去掉 `--offline`，依赖将下载到 E 盘工程内。

`-Pacceptance` 会加载独立测试夹具，创建新的超平坦世界，自动运行核心回归检查；tools/instance-smoke.ps1 还可运行最终功能专项和代表模型检查，保存截图和 JSON，然后退出。测试代码和测试实体不包含在发行 JAR 中。

发行包另通过真正 `forgeclient` 入口启动，没有依赖 userdev 映射。结果和截图见 [验收记录](docs/ACCEPTANCE.md)，接口选型见 [架构说明](docs/ARCHITECTURE.md)。
