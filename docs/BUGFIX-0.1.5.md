# Pose Studio 0.1.5 修复与使用说明

本版本为 Minecraft Java 1.20.1 / Forge 静态摆拍编辑器。项目、源码、工具链、临时文件、发行包和测试证据均位于 E 盘。没有添加动画时间轴、IK 或独立渲染引擎。

## 用户可见变化

1. F6 从当前世界主画面收集可见实体，并始终加入玩家本人。全部对象通过服务器检查后一起冻结；超过上限提示并拒绝进入，不留下部分冻结。镜头保留按 F6 时的位置。
2. 默认同一维度最多 8 个 Studio 摆拍对象，可配置为 5–10，包含玩家、冻结的已有实体和添加的模型，多个操作者共享预算。
3. Actor 模式可用左键或右键拖动整个模型；Ctrl 点击列表或模型进行多选，拖动已选模型保留选中组，整个组以相同世界 XYZ 位移移动。数值编辑同样支持多选。
4. 模型拖动和关节编辑分属 Actor / Pose 模式。空白视口仍用于镜头；滚轮或中键上下拖动调整 FOV。切换模式、关闭面板和拍照会结束模型拖动。
5. 一次完整拖动记作一次调整，撤回按钮或 Ctrl+Z 一次恢复整个组。服务器统一验证全部目标；其中一个无效也不会只移动部分对象。
6. “添加”提供当前整合包的实体注册目录，可按中文名称、注册 ID 或 Mod ID 搜索，指定 XYZ、Yaw、Pitch 或放到镜头前方，再添加并冻结。新增对象只作为临时摆拍对象，移除或退出时清理。
7. 左侧角色列表覆盖客户端已加载的非移除实体，按自由摄影机距离排序，取消玩家身体周围 96 格的旧过滤。
8. 修复 Fresh Animations 骷髅实际头部与空 head 驱动不同步的问题；实际头部跟随 head 的旋转和局部位置。默认列表进一步只显示实际主画面中有几何的骨骼，不让未使用的项圈 / 护甲层引入空节点。

## 使用步骤

- 进入世界，调整初始构图，按 F6。如果超过上限，调整镜头或服务器设置后再进入；从第一人称进入时，玩家本人也占一个名额。
- 在“角色”模式点击模型或左侧列表；Ctrl 点击可增减多选。对选中模型左拖或右拖整体移动；在右侧设置精确 Position X/Y/Z。尚未冻结的额外对象需先冻结。
- “姿势”模式只编辑主对象的关节；肘、膝仍使用连续弯曲网格，双层皮肤共同移动。
- “添加”从当前实例的注册实体目录创建临时模型。“移除”只作用于添加的对象，不删除原有世界实体。
- F8 隐藏 UI 与全部辅助显示，保持姿势、对象位置和镜头；Studio 期间也隐藏原版聊天叠层，避免最近的超限或操作错误消息盖住画面；F2 使用 Minecraft 截图。F6 退出，恢复原有对象并移除临时对象。

单人世界的配置：`<存档>/serverconfig/posestudio-server.toml`。专用服务器使用其世界 serverconfig 下同名文件：

```toml
maxStudioActors = 8
```

5 适用于较弱设备 / 较重光影，8 为默认，10 应在实际性能允许时使用。范围由 Forge 配置限制为 5–10。预算作用于 Studio 参与对象，普通未参与的背景实体由 Minecraft 正常渲染，不承诺固定帧率。服务器和客户端都应更新至 0.1.5（协议 3）。

## 原因与修复

Fresh Animations 骷髅的 `head` 没有可见 cube，实际头骨位于 `headwear/EMF_headwear2`。仅改 head 节点不能证明头骨移动。Humanoid 的头部与帽层共享 head 变换，保留资源包原层级及几何；回归比较实际头骨的渲染矩阵，并在下一帧检查撤回。

狼、鸡等模型也会把实际头部置于 body 的 EMF 子树。默认编辑节点从已有层级提取，再按当前真正渲染的 cube 路径过滤；可选 EMF 名称读取用于提高节点名称可读性。没有给这些生物添加新骨骼。“辅助”保留全部安全读取的层级。

和平难度的 hostile Mob 会在 ServerLevel 的独立 despawn 阶段消失，即使常规实体 tick 已冻结。新增 Mob 消失检查桥接仅保护已锁定对象。临时移除也通过可选 Physics Mod 桥接避免被当作死亡碎裂处理。

LrTactical 的裸 EntityType 工厂缺少 `ThrowableId`，会画紫黑占位方块。可选 EntityPlacementFactory 使用其服务端原生资源索引、物品和实体工厂补齐生成数据；实际烟雾弹纹理和模型由原模组渲染。该模型不暴露 ModelPart，因此整体 Actor 编辑可用，内部姿势明确降级；没有编造骨骼支持。

## 游戏验证范围

仅使用用户指定实例：`E:\minecrate\.minecraft\versions\1.20.1-Forge_47.4.22 Vanilla-tacz`。保留该实例原模组、FA+Player、Fresh Animations、原资源包和 ComplementaryShaders v4.7.2 光影设置，包括 Oculus、Embeddium、EMF、ETF、Skin Layers 3D、Physics Mod、TaCZ 和 LrTactical。

使用该 PCL 实例的 Forge profile 离线启动 StudioTest，新建专用测试世界；没有打开用户原有世界，没有使用真实账号认证或 PCL 图形界面登录。测试夹具与临时皮肤资源包只用于验收，不进入正式模组。

代表模型为骷髅、狼、马、鸡、兔子、苦力怕、末影人、TaCZ 靶车、LrTactical 烟雾弹。采用不同部位、XYZ 旋转、局部位置、Actor 位置和朝向，逐个比较实际渲染变化与撤回，而不是反复使用同一套动作。没有遍历整合包全部实体。

最终检查数量和清理哈希见 `ACCEPTANCE-0.1.5.md` 与 `evidence/0.1.5/validation-summary.json`。专项覆盖：启动超限不部分冻结、第一人称玩家自动加入、镜头后方实体排除、多实体持续冻结、多选组鼠标移动、数值移动、单次整组撤回、模式切换结束拖动和无效批次原子拒绝。核心回归覆盖原双层皮肤、四个新增关节、骷髅头部和退出恢复。还有八对象同画面截图。

## 兼容边界

目录列出注册类型，不保证任意 EntityType 都有可直接创建的默认视觉模型。真实玩家需要玩家连接；部分实体需要专用主人、物品、生成数据或外部骨骼 API。不能安全创建时提示失败；不能读取 ModelPart 时保留整体 Actor 编辑并解释原因。

TaCZ 靶车测试的是已有 MinecartModel 节点，不代表其独立物品靶板的内部骨骼已适配。LrTactical 烟雾弹验证原生显示资产和整体编辑，内部姿势为不支持。Rabbit 的一些 vanilla 字段在发行运行时保留 SRG 名称，可以用视口节点或数值编辑；完整 Pose 键不改名以免损坏保存文件。

Pose 仍是操作者本地摄影视图；Actor 位移和冻结由服务端管理。专用服务器、多客户端协同姿势、其他 Shader / 骨骼库、其他整合包和长时间多人压力测试未验收。可见对象按实际世界主渲染提交和可用的 EntityCulling 状态确定，没有新增像素深度读取或自制遮挡渲染器。
