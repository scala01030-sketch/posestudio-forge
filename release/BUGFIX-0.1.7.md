# Pose Studio 0.1.7 最终功能与复核

Actor 模式增加整体 Yaw / Pitch / Roll。右侧“整体操作：位移 / 旋转”切换工具，旋转时 X / Y / Z 分别控制俯仰、偏航、侧倾，支持拖动旋转环或模型及精确数值输入。每轴允许有限角度 ±36000°，俯仰不限 ±90°。多选对象在各自原点旋转，增加相同角度，保持位置与内部 Pose；一次拖动记一次撤回，保留十步历史。

旋转在 EntityRenderDispatcher 调用原实体渲染器时包裹 PoseStack。原生 / Mod 渲染器以零朝向绘制一次，再应用 Actor 的完整旋转；临时渲染角度在 finally 中恢复，正常游戏不受影响。未改变资源包、Shader、材质或各生物骨骼。包围框和射线拾取使用同一旋转及逆旋转，标准视角对准实际旋转后的中心。骨骼节点沿原渲染矩阵捕获，因此与整体旋转一致。没有 ModelPart 的物体也可整体旋转并记录原渲染器主画面提交。

服务器预算分为两类：LivingEntity（含玩家与盔甲架）默认 8、范围 5–10；非 LivingEntity（掉落物、载具、投射物、Display 等）默认 25、范围 20–30。配置分别为 maxStudioActors 与 maxStudioProps，同一维度共享。已有冻结与目录新增对象合并分类计数；重复冻结不增加额度，任一类超限都拒绝新操作。启动仍原子冻结主画面可见对象与本人，不部分进入。

批量协议上限改为 40，覆盖 10 生物加 30 非生物；协议版本从 3 改为 4，客户端和服务器需使用同版。ActorTransform 增加 Roll，原五参数构造和缺少 Roll 的旧 JSON 按零处理。位置拖动保留三个角度，网络消息、数值多选、撤回和保存都保留 Roll。

目录创建原版 ItemEntity 时补默认铁锭，避免空物品不显示。没有新增物品资产管理系统；实际实体的物品数据仍由 Minecraft / 原 Mod 使用。预算不会截断普通背景实体渲染，也不是固定帧率承诺。

新增功能完成后不再扩展。最终构建、单元测试、真实整合包专项和回归结果见 ACCEPTANCE-0.1.7.md。仅通过指定 Vanilla-tacz 的离线新测试世界验证；独立多人服务器和所有第三方渲染器未逐一实测。
